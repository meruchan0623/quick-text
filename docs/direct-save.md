# 保存即生效

2026-10-27 起，配置只有一个已保存、生效的版本。

- 新增、编辑指令：确认保存后即可触发，无需再次应用。
- 删除、启用、停用和批量操作：确认成功后立即更新监听规则。
- 参数设置：编辑后确认保存，保存成功即生效。
- JSON / Excel 导入：选择文件和冲突策略，先查看预览；确认后一次保存并生效，取消不改配置。
- 编辑器尚未确认的输入仅留在窗口内，取消编辑不会修改已生效内容。
- 导出读取当前已保存配置。历史版本恢复仍可用，恢复成功后立即生效。

“生效”表示规则已安装到引擎，不代表立刻执行动作。暂停监听、规则停用、平台限制和导入自动化审阅要求仍然有效。保存不会解除用户暂停，也不会执行客户消息发送或其他指令动作。

## 保存与故障处理

`save_config(config)` 以 `config.revision` 检查期望版本，校验通过后一次发布。磁盘写入失败、引擎忙或配置校验失败时，不发布半成品；原配置继续生效，编辑内容可修正重试。其他窗口或外部程序已经改变配置时拒绝覆盖，先读取最新版本再处理。

`load_state` 返回当前 `active` 和 `revision`，没有草稿配置或待应用状态。`save_draft`、`apply_settings`、`discard_draft` 不再是当前 API。导入预览只存在内存中，不落盘、不改变生效配置；返回的 `token` 与预览内容和版本绑定，确认时通过 `save_config` 的 `importToken` 参数提交，并连同原始迁移数据一起保存。另一次预览会使旧 token 失效；失效确认必须重新预览，不能退化为普通保存而丢失原始数据。

`active.json` 是当前配置提交点；历史配置和对应元数据保存在 `revisions/`。旧版遗留的 `draft.json` 与 `migration-unresolved.json` 在备份允许后移动到 `legacy-unconfirmed/`，保留原始字节；不会自动启用，也不是当前配置来源。只读安全模式下不进行迁移。

## 验证边界

自动回归覆盖新增、编辑、删除的即时生效，导入预览取消与确认，保存失败、版本冲突、乱序响应、历史恢复及重启。真实键盘、输入法和目标软件的触发体验需要独立验收，不能由模拟界面或构建通过推定。

旧的 0.4 计划及验收记录中关于草稿和单独应用的内容属于历史机制；当前流程以本页和 README 为准。
