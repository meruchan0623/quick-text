# Windows 0.2.0 最终输入边界与首轮手测

这是开发包；本轮没有真实浏览器、物理键盘或中文输入法验收证据。

- Windows 仅自动执行可靠观察到的已上屏文本的即时规则。结束键模式保留配置供编辑／迁移，但本版不会自动执行；Space／Tab／Enter 等结束键正常透传，不测试消费成功。
- 组合输入 Active 或 Unknown 时不执行，不自动按 Esc 清除候选。IME 提交须匹配此前观察到的候选，且原正文未变；第三方 IME 或控件缺少证明时拒绝。
- Shift 等物理修饰键仍按住时，会在原100ms期限内等待释放后重试，超时拒绝即时触发；大小写不敏感匹配的模型测试不等于真实 Shift 输入已验。
- 目标自定义 Backspace 可能造成第一步副作用；读回检查只能停止后续输入，不能承诺绝无误删或自动撤销。

1. 保持暂停，先导出当前配置备份。添加 `qtzzx` → `测试🙂`，选择“立即触发”，动作先选“键入纯文本”，Windows 进程范围限定为本轮测试浏览器（例如实际使用的 chrome.exe 或 msedge.exe）。新 Windows 规则默认即时；导入规则的旧模式保留原样。
2. 保存、应用，再恢复。浏览器打开附带测试页面，在空白合成 input／textarea 内用物理键盘输入 `qtzzx`。记录 provider／composition／采样、revision、期望与实际；缺少可靠证据应拒绝，但拒绝不能算该控件功能支持通过。
3. 中文候选未上屏、状态未知、选区／光标／焦点改变时确认拒绝；可靠候选完整提交后的即时路径另记结果。不要用直接粘贴、跨键提交或正文变更来代替候选匹配证据。
4. 将模式改为结束键，保存应用，确认结束键正常送达、规则不自动执行。再次恢复即时模式才继续功能测试。
5. 任何错删、错窗、吞错键或覆盖新复制内容均立即暂停并保留匿名步骤；按完整验收矩阵继续其他测试。

keys（包括手动动作测试）按字符读回目标文本／光标以检测输出期间变更，可能增加延迟；实际 p95 未测，不宣称性能门槛已通过。动态网页同控件移光标的对抗用例必须实测，读回可停止后续操作，但已发生的首步副作用不能撤销。


Windows 0.2.0 keys（包括手动动作测试）需要可靠UIAutomation provider，按 Unicode 字符发送（emoji 的 UTF-16 代理对同批），每字符前后核对新鲜目标与预期正文前缀，并有界等待消费；正文或光标改变即停止后续。所有路径的paste／HTML／文件／图片发送后返回 unknown 并停止剩余步骤，不证明目标已接收。手动测试不能跳过键入provider检查；自动替换中需要核对正文的快捷键及非导航按键发送后也会unknown停止后续；手动独立快捷键没有该自动替换限制。复杂多步骤不作为完整交付／实机验收通过。
