# Windows 0.3.0 输入输出重构

日期：2026-10-15。参考 espanso v2.4.1，commit `a87d1723f47a59e38d370e2f0c636d66d568b8f6`。

## 定位出的缺陷

1. 旧物理输入链路仍要求短时有效的 UIA 可编辑元数据，浏览器/Electron 的控件识别慢、缺失或变化时，匹配会被放弃。`windows_physical.rs` 原 `METADATA_MS` 为 200，`candidate_protected` 对未知原生控件要求 UIA 阳性证明。旧“无需 UIA”说明与代码不符。
2. 无法确认输入法状态时，旧 `unknown_erasure` 仅接受完整纯字母段，数字或标点缩写会被拒绝。中文 HKL 无法区分拼音中文模式与英文模式，不能用它推断正在选字。
3. 旧逐字输出每字符调用 `observer::fresh` 等待正文变化，目标不提供文本证据就停止；粘贴后 `UNVERIFIED_STOP` 会让后续宏步骤停止。
4. 旧物理缓冲与 observer 候选入口共存，事件、焦点代次和异步采样之间存在耦合。旧实现还整体禁用了终止键触发。
5. 本次只读检查发现，当前用户正式 `active.json` 只有一条启用规则，范围仅 `notepad.exe`。因此聊天软件不触发还可能是规则范围所致；升级不擅自扩大用户规则范围。之前导入样本的 53 条不代表当前正式配置存在 53 条。

## 新实现范围

Windows 检测与注入采用固定版本的 espanso 原生源代码，通过 Rust 适配到本项目的匹配与执行接口。没有运行外部 Espanso 服务，没有引入上游 YAML 配置、匹配器、包管理器或界面。具体文件、上游链接与设计依据见 [源码核对](espanso-source-audit.md) 和 [第三方声明](../THIRD_PARTY_NOTICES.md)。

保留本项目的 Quicker JSON 导入、草稿/生效版本、分组、进程范围、黑名单、大小写、参数、自定义动作、键鼠录制、逐字键入与整段粘贴区分，以及剪贴板多格式/并发变更保护。UIA 不再是逐键识别、退格和输出的硬依赖；它可提供明确密码/只读状态的附加阻止证据。无法识别的控件不能保证密码检测完整。

支持立即、空格和分号触发。RawInput 不具备拦截目标按键的能力，所以 Tab/Enter 不作为自动触发键；不先发送回车再补救聊天消息。空格已进入目标后才退格替换，保留空格与否按规则设置处理。中文选字时空格可能选词，该场景不能用英文模式的结果代替。

输入输出为尽力发送：系统接受输入不等于控件已经消费，结果显示 `unknown`。真正的焦点/版本/暂停/取消/用户干预仍中止执行；不因缺少正文读回而中止后续动作。页面脚本在同一控件内移动光标、输入法选词等行为仍可能造成与物理字符数量不同的结果。

原有 Esc/Backspace 偏好仍保留于配置，当前 Windows 后端统一按缩写长度退格，未执行 Esc 关闭候选。界面明确显示这一限制；没有把保留配置误称为该行为已经支持。

独立对抗评审发现并复核修复：剪贴板失败时 Paste 静默降级 Keys、热键部分提交后的释放缺失、AltGr 前缀与释放等待、积压旧候选抢占执行、旧打包入口遗漏对应源码。另移除上游 `RIDEV_NOLEGACY`：espanso 原项目有独立 worker，本应用输入组件与管理窗口同进程，保留该标志会影响管理界面接收键盘。

## 使用新版

退出旧程序托盘中的“退出全部”，解压新版绿色包并运行 `quicker-text.exe`。启动默认暂停；应用设置后恢复监听。确认缩写启用、操作内容正确、生效进程包含目标程序。只填 `notepad.exe` 的指令仍只在记事本执行。

绿色包包含可执行文件、完整对应源码、上游许可、补丁清单与 SHA256。用户原来的规则和数据目录不迁移、不覆盖。自动验收配置由 `scripts/create-input-acceptance-config.ps1` 生成在新建的隔离目录，不能把它覆盖到正式配置。
