资料截点与本轮开发：2026-10-14。目标索引来自《Quicker 文本指令跨平台开发计划》，不将开发完成、静态预览、自动检查或原生发送返回等同端到端通过。

## 已取得证据

- Windows调试版真实启动并通过GUI新增合成规则：`qtzzx` / `notepad.exe` / immediate / keys，正文为合成中文emoji。保存后显示v0草稿待应用，应用后v1同步，恢复/暂停状态显示正确。此项只覆盖T11草稿发布子用例，不能把整个T11写成通过。
- T01真实键盘触发未完成：自动桌面输入属于外部注入，会被安全过滤。T05原生动作测试未完成：验收时焦点被其他任务切换，桌面状态不可用；现已暂停。用户后续自行实测。
- `cargo check -p quicker-platform --target aarch64-apple-darwin`通过，包含真实macOS adapter的FFI、匹配、执行、剪贴板和权限代码。当前宿主Windows，没有Mac framework链接、完整Tauri Mac构建或运行证据。
- 完整Mac应用检查尝试了`cargo check -p quicker-text --target aarch64-apple-darwin`，在`objc2-exception-helper v0.1.1` Objective-C `try_catch.m`构建时失败：`failed to find tool "cc": program not found`。需用户Mac/Xcode工具链继续检查；不是Rust platform adapter自身的编译报错。
- 0.1.0历史检查曾通过78项（71 domain、3 native、4 store）；0.2.0最终集成检查通过110项（86 domain、20 native、4 store），`npm run build`通过（36 modules）。自动测试不涵盖系统输入消费、目标应用、IME、权限、剪贴板竞态或延迟p95。
- Windows只读控件枚举发现本机记事本为NotepadTextBox→RichEditD2DPT；可用于后续English US+ASCII+非IME+真实正文获焦测试，但不能称作输入hook验收。此前自动触发范围仅原生Edit/RichEdit；0.2.0新增特定TextPattern2观察路径，浏览器/中文实机仍未验。
- Windows NSIS包已生成，交付前按最终改动重建并记录hash。Mac签名/公证凭据未提供，未生成Mac已验收安装包。

## 推荐最小实测顺序

1. Windows先安装0.2.0开发包，保持暂停，导出当前配置备份；用English US和普通记事本创建`qtzzx`限定规则，仅用合成正文。历史只读枚举发现本机RichEditD2DPT，可作为待测对照；0.2.0还支持特定UIAutomation TextPattern2观察路径，须在目标正文获焦时核对provider与可靠状态。无法取得可靠文本／光标／inactive composition证据应拒绝，不能仅按控件名推断功能已支持。浏览器及中文IME按专门矩阵逐项实测。
2. 测保存/取消/应用revision，再恢复监听以即时规则依次测keys、paste；结束键模式仅确认透传与不执行；每次变更都保存并应用，测试后暂停。
3. 先测文件预检失败和切窗/继续输入取消，再测HTML/图片/file对象及剪贴板新复制保护。任何错删、错窗、吞错键、覆盖新复制即暂停并记录完整步骤。
4. 最后测B/多步骤/录制/倍速、物理键冲突和登录项；副作用不自动回滚，用空白文件或专门测试窗口。
5. Mac先本机编译/完整链接，再授予辅助功能和输入监控；只用白名单ABC/U.S.与TextEdit bundle范围重复同一套步骤。Secure Input、IME/dead-key布局和未知焦点应拒绝。没有签名/公证凭据，不将开发app称作正式分发安装包。登录启动已有用户级LaunchAgent，仍需Mac自己登录验收。

性能门槛仍未验：短静态keys p95<100ms是待测目标，clipboard/HTML需分别建立基线；本轮没有真实系统输入延迟分布，不给虚构数字。

## 0.2.0 浏览器与中文输入增量

规则IME删除方式支持继承全局（null/缺省），旧显式escape/backspace保留。状态页提供当前目标provider、进程、composition、采样时间与阻止原因。Windows目标观察仅在可靠provider证明安全状态时匹配，不因此将浏览器或中文IME标记通用支持。匿名页面和逐项用户手测矩阵见 [浏览器与IME手测](browser-ime-manual-tests.md)；本轮未自动执行浏览器验收，T01/T02/T04及安全竞态仍待真实键盘证据。


最终Windows限制：仅即时已上屏自动触发；Active/Unknown不执行，IME提交须匹配已观察候选且正文未变。结束键透传不自动执行，Shift持键时在原100ms期限内等待释放重试，超时拒绝。自定义Backspace首步副作用无法由读回撤销。首轮浏览器步骤见 [Windows 0.2.0手测](windows-0.2.0-test-notes.md)。


Windows 0.2.0 keys（包括手动动作测试）需要可靠UIAutomation provider，按 Unicode 字符发送（emoji 的 UTF-16 代理对同批），每字符前后核对新鲜目标与预期正文前缀，并有界等待消费；正文或光标改变即停止后续。所有路径的paste／HTML／文件／图片发送后返回 unknown 并停止剩余步骤，不证明目标已接收。手动测试不能跳过键入provider检查；自动替换中需要核对正文的快捷键及非导航按键发送后也会unknown停止后续；手动独立快捷键没有该自动替换限制。复杂多步骤不作为完整交付／实机验收通过。
